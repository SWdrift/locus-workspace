# 文档规范

本页定义文档结构、事实归属、写作规则、事实核查、注释与文案要求以及审阅判据。

## 文档结构

以下结构规则适用于项目说明和参考文档。设计方案与决定采用 [Agent Notes](../.agents/notes/AGENTS.md) 的格式和生命周期。

文档的主题和所在层级决定其范围。正文完整描述本主题；介绍下级模块时，只写用途、职责和高层行为，细节链接到所属页面。参考文档也不能以“完整”为由收录其他主题的契约。测试机制、夹具和运行方式放在最低所属层级，上层只链接。

正文按主题和查阅需求组织，先定义范围，再说明契约与行为。参考文档跟随其主题归属，不因采用参考体裁就集中到另一层目录。起稿时先确定主题与位置，限定细节层级，再安排内容；越界细节移回所属页面并留下链接。

## 文档归属

每项事实只有一个完整定义的位置，其他页面链接到该处。职责按下表划分；需要新主题时才建立文档，不为凑齐分类制造空目录或空页。

## 写作规则

- **写当前事实。** 普通正文描述现行机制，不写“新增了”“以后将”。未实施方案进入提案，不得冒充已交付行为；历史、备选方案与变更过程留在各自所属记录。
- **标题使用中文。** 页面和章节标题使用中文；产品名、文件名、命令、协议名和路径标识等专有名词保留原文。
- **契约完整，范围克制。** 写清行为、输入输出、失败、时序、所有权和限制；不要复述代码、推演每条分支或解释显而易见的实现。
- **同次更新事实所有者。** 改变行为或契约时更新所属文档；移动文件或修改标题时修复活动入链。有长期取舍才按[创建条件](../.agents/notes/AGENTS.md#何时需要写一份)写 Agent Note，机械调整不需要新记录。
- **一段一物理行。** 使用编辑器软换行；代码块、表格和列表保留各自格式。一个段落只承担一个主题，不堆叠多条规则与括号补充。
- **示例有依据。** 命令和代码必须对应真实入口，说明必要前提与成功判据；示例不是执行证据，未运行的内容不能附上成功结论。模板提示在成文前替换为实际内容。
- **引用所属页面。** 当前文件使用相对 Markdown 链接，细节尽量链接到具体标题；历史引用标明对应事件或版本。生成内容由其输入源更新，不维护第二份手抄目录。
- **直接表达。** 写明主体、动作和事实，使用具体类型、接口或命令名。删除口号、反复免责、无意义强调和“显然”“至关重要”等修饰。

## 事实核查

操作类声明的唯一可采信证据是实际执行：命令、参数、默认值、错误信息和平台差异都算在内。写之前按顺序做完四步。

1. **先判对象类型。** 读源码与 `package.json`，按实际实现判断模块形态，不按目录名推断；不适用于该形态的安装、配置或扩展指引一律不写。
2. **逐条实跑。** 按文档将展示的样子执行命令与配置片段，只记录观察到的输出、警告和失败；依赖缺失的密钥或网络时，写明未验证范围，不推断行为。
3. **删掉无法复现的内容。** 不凭记忆、类比或邻近模块的文档补齐字段与默认值；复现失败时改正文，不改测试。
4. **对照最新主线。** 修订旧页面前先与远端默认分支对比；主线上的过时陈述仍按代码纠正，不按旧文纠正。

## 注释与文案

代码注释与面向用户的文案属于正文，遵守同一判据：写清代码无法表达的契约，不复述代码已经表明的内容。

- **保留完整命题。** 主体与动作、条件与时机、语气（必须、可以、绝不）、否定性保证与例外、归属与副作用与失败模式与后果；删修饰与重复时，每个事实分句都必须存活。
- **公开 JSDoc** 写调用方可见的返回值区别、抛出、副作用、归属、时机与持久性；**内部与模块注释**写非局部结构、不变量、竞态顺序、安全边界和意外失败，删控制流叙述。
- **测试注释**只解释非显而易见的夹具、断言、平台适配与真实入口，不写走查。**README** 写消费方契约，架构与算法链接到所有者，不复制第二份。
- **提示词与界面文案按行为对待。** 文本、无障碍名称、占位符和格式模板一起检查；未获授权修改时只报告问题。
- **诊断信息**写失败主体或路径、被违反的规则和修正方式，不写内部执行叙述。
- **保留机制名与有意义的语气、时间或否定强调。** 只规范化装饰性强调；省略非显而易见的理由会导致误用时，保留该理由。

## 验证

文档变更交付前运行 `pnpm docs:check`。修改检查器时的运行约束见[测试系统](testing.md#文档检查)，命令与脚本入口见[实用命令](commands.md)。不要在本页复制检查器细则或测试清单。

机械检查不能证明语义正确或发现所有遗漏的文档。审阅仍需核对实现、契约与实际运行证据；无法验证时写明具体范围和缺失前提。归档记录遵循[归档与删除规则](../.agents/notes/AGENTS.md#归档与删除)，不为修补旧出链改写历史。

## 审阅清单

判据先于清单：页面应简短（常见路径只含达成结果所需的事实，穷举真相留在一层链接之后）、直观（前置条件先于依赖概念，下一步动作唯一）、友好（能识别成功、行动前理解风险、失败后可恢复）、准确（每条持久声明有唯一所有者与相称的验证路径）、可检索（稳定标题与锚点支持定向查阅）、新手可完成（无仓库背景的工程师能靠三到五个互相链接的页面重建该主题）。然后逐项检查：

- 重复正文：搜索独特措辞，确认同一规则、参数或契约没有多个维护位置。
- 层级越界：检查上层是否讲了下级实现，普通正文是否混入决定过程或事件叙事。
- 易腐副本：检查手写符号表、包清单、测试清单和完成度标记；已有源码或生成物负责时改为链接。
- 推理流水账：删除实现过程、分支证明和测试步骤复述，留下最终契约、必要证据或长期理由。
- 表达噪音：拆开多主题长段，删除空章节、模板提示、反复强调和无独立信息的句子。
