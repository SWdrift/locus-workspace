# 决策记录：带口令 SSH 私钥的凭据交付

Status: proposed

## 问题

Remote Targets 已切换到 Core CredentialRef：无口令私钥与密码目标通过受限临时文件或 Plink `-pwfile` 消费。带口令私钥仍无法在无人值守场景安全解锁：系统 OpenSSH 需要 askpass 或 TTY，不能自动去掉口令，也不能把口令放入 argv、普通环境变量、配置或日志。

## 提案

保持现有边界：SSH 协议、主机信任和身份选择交给系统 OpenSSH；CredentialRef、绑定与 Root 导入归 Core。迁移预检明确拒绝带口令私钥，不自动去口令、不删除原文件、不伪造解锁成功。

未来若需要支持，必须先冻结以下契约：

- 口令使用独立 CredentialRef 与凭据类型，还是与私钥同一受保护条目；
- 口令如何绑定到 `remote-targets`、目标资源与私钥槽，且不能扩大到其他目标；
- askpass 辅助程序如何从 Core 获得口令而不进入 argv／普通环境；临时文件、命名管道或受控 IPC 的权限与清理边界；
- 失败、取消、超时、进程强杀后的残留与可判错误。

## 备选方案

**自动执行 `ssh-keygen -p` 去口令**：禁止。改变原秘密保护，且用户未明确同意。

**把口令放入 `SSH_ASKPASS` 环境或 argv**：禁止。扩大暴露面且容易被同用户进程读取。

**共享 ssh-agent**：未采用。钥匙归属、默认身份选择与授权残留不可控。

## 验收标准

真实带口令私钥目标经显式迁移、Core 回读、配置切换后，由系统 OpenSSH 在无 TTY 场景完成登录；口令不出现在 argv、普通环境、配置、日志或输出；错误口令、取消、超时、强杀与清理均有可判行为。未完成前，迁移保持 `encrypted-key-unsupported` 阻塞。

## 风险

继续保留阻塞会让带口令私钥目标无法使用 Keyring 交付；直接删除旧支持会破坏现有目标。任何绕过都可能把口令放入 argv、环境或被同用户进程读取。完成前不得宣称这类目标已迁移或已实现无人值守解锁。
