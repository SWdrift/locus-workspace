# 决策记录：按包 i18n 文案目录

Status: implemented

## 问题

面向用户的文案原先直接写在调用点：错误消息、operation summary、字段说明、CLI 提示与诊断行散落在 Core、能力包与 CLI。文案无法集中审阅，改措辞要跨文件搜索，包与包之间也没有统一的归属规则。需求只要求“从代码中解耦到表”，不要求多语言、复数、日期格式化或运行时语言切换。

## 决定

每个 package 拥有自己的 `i18n` 表；Core 只提供机制，不持有其他包文案，也不登记包清单。

- 公开子路径 `@locus/core/i18n` 导出 `defineI18n(namespace, resources)`、`createI18nRegistry(catalogs)` 与 Core 自己的 `i18n`。
- 能力包使用 `@locus/core/i18n`，在 `src/i18n.ts` 定义本包表并在 `index.ts` 导出；CLI 在 `apps/cli/src/i18n.ts` 定义自己的表。
- 包内调用只用本包绑定：`i18n.t('literal.key', params)`。无参 key 不接受参数对象。
- 占位符固定为 `{{name}}`；单个 `{...}` 保持字面量，因此声明 `source:{kind:manual/discovery}` 等既有文本不需要转义。
- `t` 从表值推导 key 与参数：key 拼错、参数缺失或多余都编译失败；缺参数在运行期保留占位符，不抛二次错误。
- 资源值必须是单个字符串字面量。换行用 `\n`；禁止 `+` 或 `join` 拼接，否则值类型退化为 `string` 并丢失参数推导。
- 闭合联合的动态 key 使用 `as const satisfies Record<Code, keyof typeof i18n.resources>` 映射；禁止用输入或运行时 id 拼 key。
- 注册器只索引与校验：`namespace` 唯一、key 语法合法、模板非空且无未闭合占位符。它不提供 `t`，不持有内置文案，不参与 fallback。组合根从已加载模块聚合，测试按 `components/*` 目录发现；新增组件只改自己的包与既有 loader，不改 Core。
- ESLint 禁止 i18n 表以外的中文字符串与模板字面量；注释、标识符、错误码、事件名、环境变量与 SQL 不受影响。
- 文案措辞不随迁移冻结：表内文字可以继续整理，测试中的消息断言随文案同步。

## 备选方案

**引入 i18next 或 FormatJS。** 它们提供运行时语言协商、复数、ICU 与后端加载，但当前没有第二语言，也不使用复数或日期格式。i18next 的类型依靠全局声明合并，按包分表时逐 key 参数约束仍需自建包装；注册器的一致性校验也不由库提供。保留决定：出现第二语言或真实格式化需求时再引入，届时只替换 `t` 的实现，catalog、key 与调用点不变。

**全局唯一中文表。** 会让任意包修改都触碰同一文件，无法表达包归属，也违反新增组件不修改 Core 的约束。否决。

**按 locale 拆文件（`zh-CN.ts`）。** 当前只有一个 locale，文件按语言命名会暗示不存在的切换能力，并把每包自己的表误读为全局资源。决定不建模 locale；第二语言成为真实需求时再加字段与文件，调用点不变。

**外部 JSON/YAML 资源文件。** 会失去 key 与参数的字面量类型，需要加载时机与失败处理，并重新引入“表不在代码里”的运行时依赖。否决。

**把 catalog 做成 callable，调用 `text('key')`。** 少一个 `.t`，但非常规，类型错误与 IDE 提示更怪；`i18n.t` 与 i18next 习惯一致。否决。

**让注册器提供 `t(namespace, key, params)`。** 形成第二个翻译入口，需要额外的 locale 选择与未知 key 处理，却没有人使用。注册器只做索引与装配校验。

## 后果

- 文案改动集中到各包一张表；operation 声明、错误构造与 CLI 提示共享同一取值方式。
- 类型系统承担 key 与参数校验，注册器承担跨包 namespace 唯一性，ESLint 承担“文案不得留在调用点”。
- 代价是长 summary 与字段说明在表中形成较长物理行；Prettier 不折字符串，这是保住字面量类型与参数推导的必要取舍。
- 结构化校验允许名词标签作为 `{{field}}` 参数；整句仍属于表。若未来出现词序差异明显的第二语言，这些结构模板需要重新设计，而不是继续拼接片段。
- 未引入 locale、fallback、复数与日期格式化能力；这些在真实需求出现前不建设。
